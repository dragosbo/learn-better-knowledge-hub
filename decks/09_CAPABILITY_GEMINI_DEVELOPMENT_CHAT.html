Ledger Architecture

The Dual-Layer Storage Contract: Raw Markdown & Typed AST

To support both human code reviewers and autonomous LLM agents, prompt history is maintained in two synchronized formats: a human-readable Git markdown ledger and a strictly typed TypeScript data module.

Typed Contract (src/data/geminiChatData.ts)
export interface ChatEntry {
  id: string;
  number: number;
  session: number;
  timestamp: string;
  userPromptVerbatim: string;
  assistantResponseMarkdown: string;
  capabilityPercent: number;
  cumulativePercent: number;
  quotaSignal: {
    estimatedTokens: string;
    quotaStatus: 'safe' | 'moderate' | 'near-limit';
  };
}

Quality Engineering

Anti-Slop Discipline: Preventing Prompt Regressions

When models generate code across successive iterations, they risk introducing "AI slop": boilerplate placeholders, truncated code snippets, forgotten requirements, and unsolicited conversational preambles.

❌ AI Slop Patterns Rejected
  • Placeholder Comments: Inserting // TODO: implement later or omitting existing logic.
  • Conversational Fluff: Prepending *"Sure, I would be delighted to help with that!"* before code edits.
  • Mock Fallbacks: Hardcoding fake data instead of writing real API/file integration.
  • Unprompted Chatbots: Injecting unsolicited AI assistant floating widgets.
✅ Learn Better Discipline Enforced
  • Pristine Full-Block Writes: Components written in full with zero placeholder gaps.
  • Strict TypeScript Interfaces: Every endpoint returns a typed JSON schema.
  • Regression Baseline: Prior prompt outputs serve as regression test vectors.
  • Immediate Compilation: Every change verified with compile_applet.
🎯 Result: Over 15,000 lines of robust, production-grade code created across 29 turns without breaking pre-existing features.
Resource Stewardship

Daily Quota Pacing & Token Optimization

AI Studio development operates within daily token and request limits. Capability 09 embeds telemetry tracking token usage per prompt and provides concrete pacing guidelines.

1. Composite Batching

Instead of issuing 4 micro-prompts for small CSS tweaks, batch instructions into 1 comprehensive specification prompt.

Conserves ~30k tokens/day
2. Targeted File Scopes

Inspect only the exact line range needed (e.g. lines 100–140) rather than dumping 1,500-line monolithic files into context.

Reduces context by 80%
3. Quota Status Indicators

Every entry records quotaStatus: 'safe' | 'near-limit' alerting developers when to conclude a daily development sprint.

Zero unexpected lockouts
