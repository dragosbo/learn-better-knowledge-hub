Ingestion Architecture • yt-dlp Pipeline

Zero-API-Key YouTube Ingestion: How It Works

Extracting 70 playlists, 486 clips, and dual-language subtitles without burning Google YouTube Data API quota.

1

Flat Playlist Crawl

extract_flat=True retrieves channel tabs, playlist IDs, and video counts in milliseconds without loading heavy video web pages.

2

Subtitle Cue Parsing

Pulls WebVTT/SRV caption tracks directly. Strips timestamps, cue headers, and duplicate rolling lines into clean, human-readable .txt files.

3

Streamlined Audio

Extracts raw audio stream and converts to standard MP3 at 192kbps via reencode_audio.py, skipping heavy video stream downloads.

4

Idempotent Caching

Files already on disk are skipped instantly. Re-running read_channel.py only downloads newly added videos.

Why Not YouTube Data API v3?

API v3 caps requests at 10,000 units/day. Reading 70 playlists with videos exhausts daily quota in minutes.

Reliability Engineering • Network Defense

Anti-Bot, Cookie Auto-Detection & Proxy Resilience

Eliminating the dreaded ParseError: no element found and bot-detection blocks in corporate environments.

⚠️ The Problem: Corporate Proxies & Bot Blocks
  • × youtube-transcript-api fails with empty XML bodies when intercepting HTTP proxies strip SSL headers.
  • × YouTube serves CAPTCHA or HTTP 429 when high-frequency requests originate from shared IP ranges.
  • × Browser cookie databases (Chrome/Brave) lock sqlite files while running.
🛡️ The Solution: lib/net.py Defensive Shield
  • ✓ apply_no_proxy_env() unsets conflicting proxy variables before invoking network sockets.
  • ✓ find_cookies() checks code/cookies.txt automatically, enabling authenticated requests without Chrome file lock issues.
  • ✓ Custom User-Agent rotation and exponential backoff retry algorithms in lib/youtube.py.
import net; net.apply_no_proxy_env() Guarantees reliable execution on iPad, WSL, macOS, and Linux
