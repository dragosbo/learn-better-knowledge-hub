Incident Postmortem • WebKit ITP Breakdown

The iPadOS 401 WebKit Crisis: Why All Browsers Failed

Following an iPadOS update, preview frames returned HTTP 401 Unauthorized across Safari, Chrome, and Brave.

1. Universal WebKit Engine Mandate

On iOS and iPadOS, Apple mandates that every browser—whether Chrome, Brave, Edge, or Safari—must use the operating system's internal WebKit framework. A security policy change at the OS level impacts all browsers identically.

Switching from Safari to Chrome or Brave does not bypass WebKit rules.
2. ITP Drops Cross-Origin Iframe Cookies

AI Studio embeds preview applets inside an <iframe> under a Cloud Run domain (*.run.app). iPadOS's "Prevent Cross-Site Tracking" flagged the Google authentication session cookies as third-party tracking cookies and dropped them.

Cloud Run ingress received requests without credentials → rejected with 401.
The Insight: The 401 was NOT an application bug—it was an operating system third-party cookie quarantine.

UX Engineering • Fullscreen & PWA

iPad Fullscreen Engineering: Defeating WebKit Limitations

Apple disables native requestFullscreen() inside WebKit iframe embeds. Here is how we bypass it.

Method 1: CSS Viewport

The in-app [ ⛶ ] button triggers a CSS fallback: fixed inset-0 z-50 w-screen h-screen, expanding the container over surrounding UI.

Method 2: Brave Auto-Collapse

Enabling "Hide Toolbar on Scroll" in Brave settings slides the address bar and tab strips off-screen whenever you scroll through clips or transcripts.

Method 3: Standalone PWA

Tapping "Add to Home Screen" in Safari/Brave launches the webapp via Apple's WebApp runtime with 100% zero browser UI and true edge-to-edge canvas.
