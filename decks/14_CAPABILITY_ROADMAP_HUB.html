Storage Engineering • Zero Git Bloat

Large Media Blobs: GitHub Releases vs. Git Tree Bloat

Why committing MP3s and MP4s directly to Git destroys repositories, and how GitHub Releases solves it.

❌ The Anti-Pattern: Raw Blobs in Git
  • • A few 200MB OBS recordings balloon git clone size to 5GB+
  • • GitHub completely blocks pushes containing files over 100MB
  • • AI Studio cloud containers take minutes to clone or run out of memory
  • • Git LFS incurs unexpected bandwidth limits and billing friction
✅ The Solution: GitHub Releases Assets
  • • Supports files up to 2GB per asset with zero git history impact
  • • Permanent direct CDN URLs streamable by HTML5 <audio> tags
  • • Keeps the active Git repository ultra-lean (under 30MB)
  • • Compatible with iPad/iPhone mobile uploads via web browser
URL: https://github.com/{user}/{repo}/releases/download/media-assets/notebooklm_ep01.mp3 Direct Streaming CDN
Mobile Ergonomics • Interim Staging

Google Drive: Interim Mobile Scratchpad, Not Database

Leveraging Google Drive and iCloud Drive for frictionless iOS file capture without database coupling.

1. Two-Tap Mobile Save

When ChatGPT Voice or NotebookLM generates an audio file on iPhone, saving to Google Drive via iOS Share Sheet takes two taps with zero terminal friction.

2. Desktop Staging Bridge

When seated at Windows Desktop, drag media from LearnBetter_Staging/ into GitHub Releases and sync markdown into the monorepo.

3. Why Not Live Database?

Using Drive as a live backend requires complex OAuth consent screens, token refresh daemons, and hits cross-origin audio streaming blocks.

Golden Rule: Drive is for mobile transit; Git & GitHub Releases are for permanent architecture.
Repository Governance • Zero Fragmentation

Single Central Monorepo: The Anti-Fragmentation Standard

Why creating one repository per AI model fractures mental models and destroys AI Studio's global context window.

Fractured Multi-Repo Nightmare
  • • AI Studio cannot read across repositories without configuring multiple GitHub tokens.
  • • Gemini cannot cross-reference lessons written by Claude or Kiro.
  • • Managing four git branches on an iPad touch interface is error-prone.
  • • Knowledge is scattered across multiple repositories with separate issue trackers.
Unified Monorepo Architecture
  • • Gemini in AI Studio inspects all 15 Python tools, Claude lessons, and Kiro guides in one turn.
  • • Atomic commits: one PR updates Python code, tests, and documentation synchronously.
  • • Single deployable web container with zero git submodule overhead.
  • • Uniform full-text search across all AI assistant contributions.
Result: 1 Repository • 1 Knowledge Base • 0 Submodule Friction
